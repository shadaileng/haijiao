## 1. 需求概述

### 1.1 功能定义

每个使用海角助手的用户设备加入一个 P2P 网络，可以实时共享自己的足迹（浏览历史）和推荐内容。其他在线用户可以看到这些共享数据，实现去中心化的内容发现。

### 1.2 核心特性

| 特性 | 说明 |
|------|------|
| 实时共享 | 设备必须同时在线才能共享数据 |
| 全局发现 | 所有用户共享一个全局池，任何用户可看到其他用户的共享 |
| 设备标识 | 以设备作为主体，无需账号关联 |
| 分阶段实施 | 先实现基础 P2P 框架，再实现业务功能 |

### 1.3 技术约束

- 部署在 Cloudflare Workers，无法维持长连接
- Worker 是无状态 HTTP handler，每次请求最多 30 秒 CPU 时间
- 需要兼容现有 Vue 3 + Vant 4 移动端架构

### 2.2 组件说明

| 组件 | 位置 | 职责 |
|------|------|------|
| 信令服务器 | Cloudflare Worker | 协助 P2P 节点交换连接信息（SDP/ICE） |
| P2P 管理器 | 客户端 `src/p2p/` | 管理 WebRTC 连接、数据广播 |
| 设备标识 | 客户端 `src/p2p/identity.ts` | 生成和管理设备唯一 ID |
| P2P Store | 客户端 `src/stores/p2p.ts` | 管理 P2P 网络状态 |

### 2.3 为什么选择 WebRTC + Worker 信令

| 方案 | 优点 | 缺点 | 适用性 |
|------|------|------|--------|
| **WebRTC + Worker 信令** | 浏览器原生支持、NAT 穿透、加密传输 | 需要信令服务器、NAT 穿透可能失败 | ✅ 推荐 |
| Durable Objects | 支持 WebSocket 长连接 | 成本高、复杂度高 | ❌ 过重 |
| 纯 HTTP 轮询 | 实现简单 | 延迟高、资源浪费 | ❌ 不适合实时 |
| WebTorrent | 适合内容分发 | 不适合实时通信 | ❌ 场景不匹配 |

## 4. 数据结构设计

### 4.1 设备标识（浏览器指纹）

使用浏览器 API 生成设备指纹作为设备 ID，确保同一设备在不同会话中保持一致。

```typescript
// src/p2p/identity.ts

interface DeviceIdentity {
  id: string        // 浏览器指纹哈希值
  nickname?: string // 可选的设备昵称
  createdAt: number // 创建时间
  lastActive: number // 最后活跃时间
}

// 生成浏览器指纹
async function generateFingerprint(): Promise<string> {
  const components = [
    navigator.userAgent,
    navigator.language,
    screen.width + 'x' + screen.height,
    screen.colorDepth,
    new Date().getTimezoneOffset(),
    navigator.hardwareConcurrency || 'unknown',
    navigator.deviceMemory || 'unknown',
    navigator.platform,
    navigator.maxTouchPoints || 0,
  ];
  
  const fingerprint = components.join('|');
  const encoder = new TextEncoder();
  const data = encoder.encode(fingerprint);
  const hashBuffer = await crypto.subtle.digest('SHA-256', data);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}

// 从 localStorage 加载或生成
async function getOrCreateIdentity(): Promise<DeviceIdentity> {
  const key = 'p2p_identity';
  const stored = localStorage.getItem(key);
  if (stored) {
    const identity = JSON.parse(stored);
    identity.lastActive = Date.now();
    localStorage.setItem(key, JSON.stringify(identity));
    return identity;
  }
  const fingerprint = await generateFingerprint();
  const identity: DeviceIdentity = {
    id: fingerprint,
    createdAt: Date.now(),
    lastActive: Date.now(),
  };
  localStorage.setItem(key, JSON.stringify(identity));
  return identity;
}
```

### 4.2 设备在线状态

```typescript
// src/stores/p2p.ts

interface PeerDevice {
  id: string              // 设备 ID（指纹）
  nickname: string        // 设备昵称（可自定义，默认显示 ID 前 8 位）
  status: 'online' | 'offline' | 'connecting'
  lastHeartbeat: number   // 最后心跳时间
  activityScore: number   // 活跃度分数（心跳频率 × 在线时长）
  sharedItems: SharedItem[] // 该设备的共享数据
  connectedAt: number     // 首次连接时间
}

interface DeviceListState {
  devices: Map<string, PeerDevice>  // 设备列表
  maxOfflineDevices: number         // 最大记录离线设备数（默认 10）
  lastSync: number                  // 最后同步时间
}
```

**活跃度计算规则：**
- 每次心跳 +10 分
- 每在线 1 小时 +5 分
- 离线后分数每小时 -5 分
- 设备列表按活跃度降序排列
- 在线设备不计入离线设备数限制

**设备昵称规则：**
- 默认显示：`设备 {ID前8位}`
- 用户可自定义昵称
- 昵称存储在本地 localStorage
- 昵称同步到 P2P 网络（其他设备可见）

### 5.2 API 端点

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| POST | `/api/p2p/register` | 注册/心跳 | `{ peerId: string }` | `{ success: boolean, peers: string[] }` |
| POST | `/api/p2p/offer` | 发送 SDP offer | `{ from: string, to: string, sdp: string }` | `{ success: boolean }` |
| POST | `/api/p2p/answer` | 发送 SDP answer | `{ from: string, to: string, sdp: string }` | `{ success: boolean }` |
| POST | `/api/p2p/candidate` | 发送 ICE candidate | `{ from: string, to: string, candidate: string }` | `{ success: boolean }` |
| DELETE | `/api/p2p/unregister` | 注销节点 | `{ peerId: string }` | `{ success: boolean }` |

### 5.3 Worker 内存管理

```typescript
// worker.ts

interface PeerRecord {
  id: string;
  lastSeen: number;
  // 不存储 SDP，仅转发
}

// 内存中存储活跃节点
const peers = new Map<string, PeerRecord>();

// 定期清理超时节点（30分钟无心跳，心跳间隔5分钟）
// 注意：Worker 每次请求独立，使用全局变量缓存
let lastCleanup = Date.now();
const CLEANUP_INTERVAL = 60 * 1000; // 1分钟
const PEER_TIMEOUT = 30 * 60 * 1000; // 30分钟（6倍心跳间隔）

function cleanupPeers() {
  const now = Date.now();
  if (now - lastCleanup < CLEANUP_INTERVAL) return;
  
  for (const [id, peer] of peers) {
    if (now - peer.lastSeen > PEER_TIMEOUT) {
      peers.delete(id);
    }
  }
  lastCleanup = now;
}
```

## 6. 客户端实现

### 6.1 P2P 管理器

```typescript
// src/p2p/manager.ts

import { ref, computed } from 'vue';
import { getOrCreateIdentity } from './identity';
import { signalingClient } from './signaling';

class P2PManager {
  private identity = getOrCreateIdentity();
  private peers = new Map<string, {
    connection: RTCPeerConnection;
    dataChannel?: RTCDataChannel;
  }>();
  
  private localStream?: MediaStream;
  private onDataReceived?: (data: any) => void;
  
  constructor() {
    // 定期心跳（5分钟间隔，节省 Cloudflare Workers 免费额度）
    setInterval(() => this.heartbeat(), 5 * 60 * 1000);
  }
  
  async connect() {
    // 1. 注册到信令服务器
    const response = await signalingClient.register(this.identity.id);
    
    // 2. 与现有节点建立连接
    for (const peerId of response.peers) {
      if (!this.peers.has(peerId)) {
        await this.initiateConnection(peerId);
      }
    }
  }
  
  private async initiateConnection(peerId: string) {
    const pc = new RTCPeerConnection({
      iceServers: [
        { urls: 'stun:stun.l.google.com:19302' },
        { urls: 'stun:stun1.l.google.com:19302' },
      ],
    });
    
    // 创建数据通道
    const dc = pc.createDataChannel('shared-data', {
      ordered: true,
    });
    
    dc.onmessage = (event) => {
      this.handleMessage(peerId, JSON.parse(event.data));
    };
    
    pc.onicecandidate = (event) => {
      if (event.candidate) {
        signalingClient.sendCandidate(
          this.identity.id,
          peerId,
          event.candidate.toJSON()
        );
      }
    };
    
    pc.onconnectionstatechange = () => {
      if (pc.connectionState === 'disconnected') {
        this.peers.delete(peerId);
      }
    };
    
    this.peers.set(peerId, { connection: pc, dataChannel: dc });
    
    // 创建并发送 offer
    const offer = await pc.createOffer();
    await pc.setLocalDescription(offer);
    
    await signalingClient.sendOffer(
      this.identity.id,
      peerId,
      pc.localDescription!.toJSON()
    );
  }
  
  broadcast(data: any) {
    const message = JSON.stringify(data);
    for (const [peerId, peer] of this.peers) {
      if (peer.dataChannel?.readyState === 'open') {
        peer.dataChannel.send(message);
      }
    }
  }
  
  private async heartbeat() {
    await signalingClient.heartbeat(this.identity.id);
  }
  
  disconnect() {
    for (const [peerId, peer] of this.peers) {
      peer.connection.close();
    }
    this.peers.clear();
    signalingClient.unregister(this.identity.id);
  }
}

export const p2pManager = new P2PManager();
```

### 7.2 设备列表页面

显示当前 P2P 网络中的所有设备及其在线状态，按活跃度排序：

```vue
<!-- src/components/DeviceList.vue -->
<template>
  <div class="device-list">
    <van-cell-group inset>
      <van-cell title="在线设备" :value="`${onlineCount}/${devices.length}`" />
      <van-cell
        v-for="device in sortedDevices"
        :key="device.id"
        :title="device.nickname"

      >

          </van-tag>
        </template>
      </van-cell>
    </van-cell-group>
  </div>

<script setup lang="ts">
import { computed } from 'vue';
import { useP2PStore } from '@/stores/p2p';

const p2pStore = useP2PStore();

// 按活跃度排序：在线设备优先，然后按活跃度分数降序
const sortedDevices = computed(() => {
  return Array.from(p2pStore.deviceList.devices.values())
    .sort((a, b) => {
      // 在线设备优先
      if (a.status === 'online' && b.status !== 'online') return -1;
      if (a.status !== 'online' && b.status === 'online') return 1;
      // 同状态按活跃度分数降序
      return b.activityScore - a.activityScore;
    });
});

const onlineCount = computed(() => 
  sortedDevices.value.filter(d => d.status === 'online').length
);

const formatDeviceLabel = (device: any) => {
  const statusText = device.status === 'online' ? '在线' : '离线';
  const activityText = `活跃度: ${device.activityScore}`;
  return `${statusText} · ${activityText}`;
};
</script>
```

## 8. 隐私与安全

### 8.1 数据最小化

| 共享数据 | 说明 | 隐私级别 |
|----------|------|----------|
| 设备 ID | 随机生成，可重置 | 低（匿名） |
| 足迹类型 | user/topic | 低 |
| 足迹 ID | 用户/帖子 ID | 中 |
| 足迹标题 | 昵称/标题 | 中 |
| 推荐理由 | 用户输入 | 中 |

### 8.2 隐私保护措施

1. **浏览器指纹**：使用浏览器特征生成唯一 ID，不收集额外个人信息
2. **指纹可重置**：用户可随时清除浏览器指纹，生成新 ID
3. **本地存储**：共享数据仅存储在本地，不上传到服务器
4. **实时传输**：数据仅在节点间实时传输，不持久化
5. **选择性共享**：用户可控制是否启用 P2P 共享
6. **设备数限制**：默认只记录前 10 个设备的数据，避免数据过多
7. **无追踪**：Worker 信令服务器不记录用户行为

### 8.3 安全措施

1. **WebRTC 加密**：所有 P2P 通信自动加密
2. **HTTPS**：Worker 通过 HTTPS 提供服务
3. **无敏感数据**：不共享账号、密码等敏感信息
4. **连接验证**：通过信令服务器验证节点身份

## 9. 故障处理

### 9.1 NAT 穿透失败

当 WebRTC 无法直接连接时：
- 回退到 TURN 服务器（可选）
- 或仅通过 Worker 中继（性能降级）

### 9.2 节点离线

- 心跳超时后自动清理
- 定期重新扫描活跃节点
- 本地数据保留，等待重新连接

### 9.3 数据冲突

- 使用时间戳解决冲突
- 较新的数据覆盖旧数据
- 同一设备的相同 ID 只保留最新

## 10. Cloudflare Workers 流量消耗分析

### 10.1 免费额度

| 指标 | 免费额度 |
|------|---------|
| 每日请求数 | 100,000 次 |
| 出站流量 | 10GB/月 |
| CPU 时间 | 10ms/请求 |

### 10.2 单设备流量消耗

| 操作 | 请求大小 | 频率 | 每日消耗 |
|------|---------|------|---------|
| 心跳 | ~100B | 每 5 分钟 | 288 次 |
| 注册/注销 | ~200B | 连接时 | 2 次 |
| SDP 交换 | ~2KB | 连接时 | 2-4 次 |
| ICE 候选 | ~500B | 连接时 | 5-10 次 |
| **合计** | ~3KB | — | **~300 次/设备** |

### 10.3 多设备场景

| 在线设备数 | 每日请求数 | 是否超限 |
|-----------|-----------|---------|
| 10 个 | 3,000 | ✅ 未超 |
| 30 个 | 9,000 | ✅ 未超 |
| 50 个 | 15,000 | ✅ 未超 |
| 100 个 | 30,000 | ✅ 未超 |
| 333 个 | 100,000 | ✅ 达到上限 |

**结论：5 分钟心跳间隔下，免费额度可支持约 300 个设备同时在线。**

### 10.4 心跳频率对比

| 心跳间隔 | 每日请求数/设备 | 支持设备数 |
|---------|----------------|-----------|
| 30 秒 | 28,800 | 3 个 |
| 1 分钟 | 14,400 | 6 个 |
| 5 分钟 | 2,880 | 34 个 |
| 10 分钟 | 1,440 | 69 个 |

### 10.5 优化策略

1. **5 分钟心跳**：平衡实时性与流量消耗
2. **30 分钟超时**：避免清理过于频繁
3. **批量清理**：每次请求只清理一次超时节点
