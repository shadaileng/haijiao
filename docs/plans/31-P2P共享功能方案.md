## ⚠️ 废弃说明

当前实现存在架构缺陷：WebRTC 信令需要 SDP/ICE 交换，但 Cloudflare Worker 是无状态 HTTP 处理器，无法主动推送消息给目标设备。`handleOffer`/`handleAnswer`/`handleCandidate` 只是返回成功，没有实际转发消息。

**废弃原因：**
1. Worker 无法转发信令消息（SDP/ICE）给目标设备
2. 设备无法建立 WebRTC 连接
3. 需要重新设计信令机制（D1 存储 + 轮询，或 WebSocket + Durable Object）

**状态：** 所有 P2P 代码已从项目中移除，等待重新设计。

## 1. 需求概述

### 1.1 功能定义

每个使用海角助手的用户设备加入一个 P2P 网络，可以实时共享自己的足迹（浏览历史）和推荐内容。其他在线用户可以看到这些共享数据，实现去中心化的内容发现。

### 1.2 核心特性

| 特性 | 说明 |
|------|------|
| 实时共享 | 设备必须同时在线才能共享数据 |
| 全局发现 | 所有用户共享一个全局池，任何用户可看到其他用户的共享 |
| 设备标识 | 以设备作为主体，无需账号关联 |
| 分阶段实施 | 先实现基础 P2P 框架，再实现业务功能 |

### 1.3 技术约束

- 部署在 Cloudflare Workers，无法维持长连接
- Worker 是无状态 HTTP handler，每次请求最多 30 秒 CPU 时间
- Worker 内存在不同 Isolate 间不共享，需要 D1 持久化设备列表
- 需要兼容现有 Vue 3 + Vant 4 移动端架构

### 2.2 组件说明

| 组件 | 位置 | 职责 |
|------|------|------|
| 信令服务器 | Cloudflare Worker | 协助 P2P 节点交换连接信息（SDP/ICE） |
| D1 数据库 | Cloudflare D1 | 持久化存储设备列表，解决 Worker 内存不共享问题 |
| P2P 管理器 | 客户端 `src/p2p/` | 管理 WebRTC 连接、数据广播 |
| 设备标识 | 客户端 `src/p2p/identity.ts` | 生成和管理设备唯一 ID |
| P2P Store | 客户端 `src/stores/p2p.ts` | 管理 P2P 网络状态 |

### 2.3 为什么选择 WebRTC + Worker 信令 + D1

| 方案 | 优点 | 缺点 | 适用性 |
|------|------|------|--------|
| **WebRTC + Worker 信令 + D1** | 浏览器原生支持、NAT 穿透、加密传输、设备列表持久化 | 需要信令服务器、NAT 穿透可能失败 | ✅ 推荐 |
| Durable Objects | 支持 WebSocket 长连接 | 成本高、复杂度高 | ❌ 过重 |
| 纯 HTTP 轮询 | 实现简单 | 延迟高、资源浪费 | ❌ 不适合实时 |
| WebTorrent | 适合内容分发 | 不适合实时通信 | ❌ 场景不匹配 |
| Worker 内存 | 简单快速 | 内存不共享、设备发现不可靠 | ❌ 已弃用 |

## 4. 数据结构设计

### 4.1 D1 数据库表

```sql
-- p2p_peers 表：存储在线设备信息
CREATE TABLE IF NOT EXISTS p2p_peers (
  id TEXT PRIMARY KEY,           -- 设备 ID（浏览器指纹哈希）
  nickname TEXT NOT NULL DEFAULT '',  -- 设备昵称
  last_seen INTEGER NOT NULL DEFAULT 0  -- 最后心跳时间戳
);

-- 清理超时设备（30 分钟无心跳）
-- 由 Worker 在每次注册/心跳时执行
DELETE FROM p2p_peers WHERE last_seen < ?;
```

**为什么用 D1 而不是 Worker 内存：**
- Cloudflare Workers 运行在 V8 Isolate 中，不同请求可能路由到不同 Isolate
- 全局变量 `p2pPeers` 只在当前 Isolate 内存有效
- 不同 Isolate 之间内存不共享，导致设备发现不可靠
- D1 是持久化数据库，所有 Isolate 共享同一份数据

### 4.2 设备标识（浏览器指纹）

使用浏览器 API 生成设备指纹作为设备 ID，确保同一设备在不同会话中保持一致。

```typescript
// src/p2p/identity.ts

interface DeviceIdentity {
  id: string        // 浏览器指纹哈希值
  nickname?: string // 可选的设备昵称
  createdAt: number // 创建时间
  lastActive: number // 最后活跃时间
}

// 生成浏览器指纹
async function generateFingerprint(): Promise<string> {
  const components = [
    navigator.userAgent,
    navigator.language,
    screen.width + 'x' + screen.height,
    screen.colorDepth,
    new Date().getTimezoneOffset(),
    navigator.hardwareConcurrency || 'unknown',
    navigator.deviceMemory || 'unknown',
    navigator.platform,
    navigator.maxTouchPoints || 0,
  ];
  
  const fingerprint = components.join('|');
  const encoder = new TextEncoder();
  const data = encoder.encode(fingerprint);
  const hashBuffer = await crypto.subtle.digest('SHA-256', data);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}

// 从 localStorage 加载或生成
async function getOrCreateIdentity(): Promise<DeviceIdentity> {
  const key = 'p2p_identity';
  const stored = localStorage.getItem(key);
  if (stored) {
    const identity = JSON.parse(stored);
    identity.lastActive = Date.now();
    localStorage.setItem(key, JSON.stringify(identity));
    return identity;
  }
  const fingerprint = await generateFingerprint();
  const identity: DeviceIdentity = {
    id: fingerprint,
    createdAt: Date.now(),
    lastActive: Date.now(),
  };
  localStorage.setItem(key, JSON.stringify(identity));
  return identity;
}
```

### 4.2 设备在线状态

```typescript
// src/stores/p2p.ts

interface PeerDevice {
  id: string              // 设备 ID（指纹）
  nickname: string        // 设备昵称（可自定义，默认显示 ID 前 8 位）
  status: 'online' | 'offline' | 'connecting'
  lastHeartbeat: number   // 最后心跳时间
  activityScore: number   // 活跃度分数（心跳频率 × 在线时长）
  sharedItems: SharedItem[] // 该设备的共享数据
  connectedAt: number     // 首次连接时间
}

interface DeviceListState {
  devices: Map<string, PeerDevice>  // 设备列表
  maxOfflineDevices: number         // 最大记录离线设备数（默认 10）
  lastSync: number                  // 最后同步时间
}
```

**活跃度计算规则：**
- 每次心跳 +10 分
- 每在线 1 小时 +5 分
- 离线后分数每小时 -5 分
- 设备列表按活跃度降序排列
- 在线设备不计入离线设备数限制

**设备昵称规则：**
- 默认显示：`设备 {ID前8位}`
- 用户可自定义昵称
- 昵称存储在本地 localStorage
- 昵称同步到 P2P 网络（其他设备可见）

### 5.3 Cloudflare D1 数据库

使用 Cloudflare D1（SQLite 兼容的 serverless 数据库）存储设备列表，解决 Worker 内存不共享问题。

**为什么不用 Worker 内存：**
- Cloudflare Workers 运行在 V8 Isolate 中，不同请求可能路由到不同 Isolate
- 全局变量 `p2pPeers` 只在当前 Isolate 内存有效
- 不同 Isolate 之间内存不共享，导致设备发现不可靠

**D1 优势：**
- SQL 查询，灵活强大
- 写后读强一致（同一 region 内）
- 免费额度：100K 读/天，10K 写/天，5GB 存储
- 适合 P2P 信令场景

**数据库表：**

```sql
CREATE TABLE IF NOT EXISTS p2p_peers (
  id TEXT PRIMARY KEY,
  nickname TEXT NOT NULL DEFAULT '',
  last_seen INTEGER NOT NULL DEFAULT 0
);
```

**wrangler.toml 配置：**

```toml
[[d1_databases]]
binding = "P2P_DB"
database_name = "haijiao-p2p"
# 不填 database_id，部署后在 Dashboard 绑定
```

**部署流程：**
1. `wrangler deploy` 部署 Worker（此时 D1 绑定未生效，P2P 功能不可用）
2. 在 Cloudflare Dashboard → Workers & Pages → haijiao-worker → Settings → Bindings
3. 添加 D1 Database 绑定，选择 `haijiao-p2p` 数据库
4. 绑定完成后 Worker 自动重启，检测到 D1 可用，P2P 功能启用

**Worker 逻辑（D1 可用检测 + 优雅降级）：**

```typescript
// worker.ts

interface Env {
  P2P_DB?: D1Database;  // 可选，D1 未绑定时为 undefined
  ASSETS: { fetch: typeof fetch };
}

const PEER_TIMEOUT = 30 * 60 * 1000;
let dbInitialized = false;

// 自动建表（幂等，仅 D1 可用时执行）
async function ensureTable(db: D1Database): Promise<void> {
  if (dbInitialized) return;
  await db.prepare(`
    CREATE TABLE IF NOT EXISTS p2p_peers (
      id TEXT PRIMARY KEY,
      nickname TEXT NOT NULL DEFAULT '',
      last_seen INTEGER NOT NULL DEFAULT 0
    )
  `).run();
  dbInitialized = true;
  console.log('[P2P] D1 database initialized');
}

// 健康检查：D1 是否可用
function checkD1Available(env: Env): boolean {
  return !!env.P2P_DB;
}

// 注册：写入设备信息，返回其他在线设备
async function handleRegister(request: Request, env: Env): Promise<Response> {
  if (!checkD1Available(env)) {
    console.log('[P2P] D1 not bound, P2P unavailable');
    return Response.json({ success: false, error: 'P2P unavailable: D1 not configured' }, { status: 503 });
  }

  const { peerId, nickname } = await request.json();
  await ensureTable(env.P2P_DB!);

  await env.P2P_DB!.prepare(
    'INSERT OR REPLACE INTO p2p_peers (id, nickname, last_seen) VALUES (?, ?, ?)'
  ).bind(peerId, nickname || `设备 ${peerId.slice(0, 8)}`, Date.now()).run();

  // 清理超时节点
  await env.P2P_DB!.prepare(
    'DELETE FROM p2p_peers WHERE last_seen < ?'
  ).bind(Date.now() - PEER_TIMEOUT).run();

  const { results } = await env.P2P_DB!.prepare(
    'SELECT id, nickname FROM p2p_peers WHERE id != ? AND last_seen > ?'
  ).bind(peerId, Date.now() - PEER_TIMEOUT).all();

  return Response.json({ success: true, peers: results });
}

// 心跳：更新 last_seen，返回其他在线设备
async function handleHeartbeat(request: Request, env: Env): Promise<Response> {
  if (!checkD1Available(env)) {
    return Response.json({ success: false, error: 'P2P unavailable' }, { status: 503 });
  }

  const { peerId, nickname } = await request.json();

  await env.P2P_DB!.prepare(
    'UPDATE p2p_peers SET last_seen = ?, nickname = COALESCE(?, nickname) WHERE id = ?'
  ).bind(Date.now(), nickname, peerId).run();

  const { results } = await env.P2P_DB!.prepare(
    'SELECT id, nickname FROM p2p_peers WHERE id != ? AND last_seen > ?'
  ).bind(peerId, Date.now() - PEER_TIMEOUT).all();

  return Response.json({ success: true, peers: results });
}

// 注销：删除设备
async function handleUnregister(request: Request, env: Env): Promise<Response> {
  if (!checkD1Available(env)) {
    return Response.json({ success: true });
  }

  const { peerId } = await request.json();
  await env.P2P_DB!.prepare('DELETE FROM p2p_peers WHERE id = ?').bind(peerId).run();

  return Response.json({ success: true });
}
```

**行为说明：**

| 场景 | `env.P2P_DB` | API 响应 | 客户端行为 |
|------|:------------:|----------|-----------|
| D1 未绑定 | `undefined` | `503 P2P unavailable` | 显示"P2P 不可用" |
| D1 已绑定 | `D1Database` | `200 success` | 正常工作 |

### 5.5 本地开发环境

本地开发时，`vite.config.ts` 中的 `handleP2PLocal` 函数会处理 `/api/p2p` 请求，无需额外启动服务。

**实现原理：**
- 在 Vite 开发服务器中间件中拦截 `/api/p2p` 请求
- 内存中存储节点列表，模拟 Worker 行为
- 自动清理超时节点（30 分钟无心跳）

| POST | `/api/p2p/unregister` | 注销节点 |
| POST | `/api/p2p/heartbeat` | 心跳保活，更新节点昵称 |
| POST | `/api/p2p/offer` | SDP 交换（返回成功） |
| POST | `/api/p2p/answer` | SDP 交换（返回成功） |
| POST | `/api/p2p/candidate` | ICE 候选（返回成功） |

const P2P_API_BASE = '/api/p2p'

interface RegisterResponse {
  success: boolean
  peers: { id: string; nickname: string }[]  // 返回完整 peer 记录
}

interface HeartbeatResponse {
  success: boolean
  peers: { id: string; nickname: string }[]  // 心跳也返回 peer 列表
}

interface SignalingResponse {
  success: boolean
}

async function request<T>(path: string, method: string, body?: unknown): Promise<T> {
  console.log(`[P2P Send] ${method} ${path}`, body)
  
  const headers = { 'Content-Type': 'application/json' }
  const response = await fetch(`${P2P_API_BASE}${path}`, {
    method,
    headers,
    body: body ? JSON.stringify(body) : undefined,
  })

  if (!response.ok) {
    throw new Error(`Signaling request failed: ${response.statusText}`)
  }

  const data = await response.json()
  console.log(`[P2P Recv] ${path}`, data)
  return data
}

export const signalingClient = {
  async register(peerId: string, nickname?: string): Promise<RegisterResponse> {
    return request<RegisterResponse>('/register', 'POST', { peerId, nickname })
  },

  async unregister(peerId: string): Promise<void> {
    await request<SignalingResponse>('/unregister', 'POST', { peerId })
  },

  async sendOffer(from: string, to: string, sdp: RTCSessionDescriptionInit): Promise<void> {
    await request<SignalingResponse>('/offer', 'POST', { from, to, sdp })
  },

  async sendAnswer(from: string, to: string, sdp: RTCSessionDescriptionInit): Promise<void> {
    await request<SignalingResponse>('/answer', 'POST', { from, to, sdp })
  },

  async sendCandidate(from: string, to: string, candidate: RTCIceCandidateInit): Promise<void> {
    await request<SignalingResponse>('/candidate', 'POST', { from, to, candidate })
  },

  async heartbeat(peerId: string, nickname: string): Promise<HeartbeatResponse> {
    return request<HeartbeatResponse>('/heartbeat', 'POST', { peerId, nickname })

### 6.2 P2P 管理器（注册后立即填充设备列表）

```typescript
// src/p2p/manager.ts

import { getOrCreateIdentity, type DeviceIdentity } from './identity'
import { signalingClient } from './signaling'
import { useP2PStore } from '@/stores/p2p'

const ICE_SERVERS: RTCIceServer[] = [
  { urls: 'stun:stun.l.google.com:19302' },
  { urls: 'stun:stun1.l.google.com:19302' },
]

const HEARTBEAT_INTERVAL = 5 * 60 * 1000

export class P2PManager {
  private identity: DeviceIdentity | null = null
  private peers = new Map<string, {
    connection: RTCPeerConnection
    dataChannel?: RTCDataChannel
  }>()
  private heartbeatTimer: ReturnType<typeof setInterval> | null = null
  private onDataCallbacks: Array<(data: unknown) => void> = []

  async initialize(): Promise<void> {
    this.identity = await getOrCreateIdentity()
  }

  getIdentity(): DeviceIdentity | null {
    return this.identity
  }

  async connect(): Promise<void> {
    if (!this.identity) {
      await this.initialize()
    }

    try {
      const response = await signalingClient.register(
        this.identity!.id,
        this.identity!.nickname
      )
      const p2pStore = useP2PStore()
      p2pStore.setStatus('connected')

      // 立即添加当前设备到设备列表
      p2pStore.updateDeviceStatus(this.identity!.id, 'online', this.identity!.nickname)

      // 立即填充所有已在线设备到设备列表（不等 WebRTC 连上）
      for (const peer of response.peers) {
        p2pStore.updateDeviceStatus(peer.id, 'online', peer.nickname)
      }

      // 发起 WebRTC 连接
      for (const peer of response.peers) {
        if (!this.peers.has(peer.id)) {
          await this.initiateConnection(peer.id)
        }
      }

      this.startHeartbeat()
    } catch (error) {
      console.error('P2P connect failed:', error)
      const p2pStore = useP2PStore()
      p2pStore.setStatus('disconnected')
    }
  }

  private startHeartbeat(): void {
    this.stopHeartbeat()
    this.heartbeatTimer = setInterval(async () => {
      if (this.identity) {
        try {
          const response = await signalingClient.heartbeat(
            this.identity.id,
            this.identity.nickname
          )
          // 心跳响应中可能有新设备，更新设备列表
          const p2pStore = useP2PStore()
          for (const peer of response.peers) {
            p2pStore.updateDeviceStatus(peer.id, 'online', peer.nickname)
          }
        } catch (error) {
          console.error('P2P heartbeat failed:', error)
        }
      }
    }, HEARTBEAT_INTERVAL)
  }

  // ... 其他方法不变
}

```
设备A (先注册)                    Worker + D1                 设备B (后注册)
     │                               │                            │
     │  1. POST /register            │                            │
     │  { peerId: A, nickname: "A" } │                            │
     │  ────────────────────────────>│  写入 D1: p2p_peers(A)     │
     │  <────────────────────────────│  返回 peers: []            │
     │                               │                            │
     │  (A 的设备列表只有自己)        │                            │
     │                               │                            │
     │  2. POST /register            │                            │
     │  { peerId: B, nickname: "B" } │                            │
     │  ────────────────────────────>│  写入 D1: p2p_peers(B)     │
     │  <────────────────────────────│  返回 peers: [{id:A, ...}] │
     │                               │                            │
     │  (B 的设备列表有 A 和 B)       │                            │
     │                               │                            │
     │  3. B 发起 WebRTC 连接 A      │                            │
     │  <════════════════════════════════════════════════════════>│
     │                               │                            │
     │  4. A 心跳                    │                            │
     │  POST /heartbeat              │                            │
     │  { peerId: A }                │                            │
     │  ────────────────────────────>│  返回 peers: [{id:B, ...}] │
     │  <────────────────────────────│                            │
     │                               │                            │
     │  (A 的设备列表更新，发现 B)    │                            │
```
    const dc = pc.createDataChannel('shared-data', {
      ordered: true,
    });
    
    dc.onmessage = (event) => {
      this.handleMessage(peerId, JSON.parse(event.data));
    };
    
    pc.onicecandidate = (event) => {
      if (event.candidate) {
        signalingClient.sendCandidate(
          this.identity.id,
          peerId,
          event.candidate.toJSON()
        );
      }
    };
    
    pc.onconnectionstatechange = () => {
      if (pc.connectionState === 'disconnected') {
        this.peers.delete(peerId);
      }
    };
    
    this.peers.set(peerId, { connection: pc, dataChannel: dc });
    
    // 创建并发送 offer
    const offer = await pc.createOffer();
    await pc.setLocalDescription(offer);
    
    await signalingClient.sendOffer(
      this.identity.id,
      peerId,
      pc.localDescription!.toJSON()
    );
  }
  
  broadcast(data: any) {
    const message = JSON.stringify(data);
    for (const [peerId, peer] of this.peers) {
      if (peer.dataChannel?.readyState === 'open') {
        peer.dataChannel.send(message);
      }
    }
  }
  
  private async heartbeat() {
    await signalingClient.heartbeat(this.identity.id);
  }
  
  disconnect() {
    for (const [peerId, peer] of this.peers) {
      peer.connection.close();
    }
    this.peers.clear();
    signalingClient.unregister(this.identity.id);
  }
}

## 8. 隐私与安全

### 8.1 数据最小化

| 共享数据 | 说明 | 隐私级别 |
|----------|------|----------|
| 设备 ID | 随机生成，可重置 | 低（匿名） |
| 足迹类型 | user/topic | 低 |
| 足迹 ID | 用户/帖子 ID | 中 |
| 足迹标题 | 昵称/标题 | 中 |
| 推荐理由 | 用户输入 | 中 |

### 8.2 隐私保护措施

1. **浏览器指纹**：使用浏览器特征生成唯一 ID，不收集额外个人信息
2. **指纹可重置**：用户可随时清除浏览器指纹，生成新 ID
3. **本地存储**：共享数据仅存储在本地，不上传到服务器
4. **实时传输**：数据仅在节点间实时传输，不持久化
5. **选择性共享**：用户可控制是否启用 P2P 共享
6. **设备数限制**：默认只记录前 10 个设备的数据，避免数据过多
7. **无追踪**：Worker 信令服务器不记录用户行为

### 8.3 安全措施

1. **WebRTC 加密**：所有 P2P 通信自动加密
2. **HTTPS**：Worker 通过 HTTPS 提供服务
3. **无敏感数据**：不共享账号、密码等敏感信息
4. **连接验证**：通过信令服务器验证节点身份

## 9. 故障处理

### 9.1 NAT 穿透失败

当 WebRTC 无法直接连接时：
- 回退到 TURN 服务器（可选）
- 或仅通过 Worker 中继（性能降级）

### 9.2 节点离线

- 心跳超时后自动清理
- 定期重新扫描活跃节点
- 本地数据保留，等待重新连接

### 9.3 数据冲突

- 使用时间戳解决冲突
- 较新的数据覆盖旧数据
- 同一设备的相同 ID 只保留最新

## 10. Cloudflare Workers 流量消耗分析

### 10.1 免费额度

| 指标 | 免费额度 |
|------|---------|
| 每日请求数 | 100,000 次 |
| 出站流量 | 10GB/月 |
| CPU 时间 | 10ms/请求 |

### 10.2 单设备流量消耗

| 操作 | 请求大小 | 频率 | 每日消耗 |
|------|---------|------|---------|
| 心跳 | ~100B | 每 5 分钟 | 288 次 |
| 注册/注销 | ~200B | 连接时 | 2 次 |
| SDP 交换 | ~2KB | 连接时 | 2-4 次 |
| ICE 候选 | ~500B | 连接时 | 5-10 次 |
| **合计** | ~3KB | — | **~300 次/设备** |

### 10.3 多设备场景

| 在线设备数 | 每日请求数 | 是否超限 |
|-----------|-----------|---------|
| 10 个 | 3,000 | ✅ 未超 |
| 30 个 | 9,000 | ✅ 未超 |
| 50 个 | 15,000 | ✅ 未超 |
| 100 个 | 30,000 | ✅ 未超 |
| 333 个 | 100,000 | ✅ 达到上限 |

**结论：5 分钟心跳间隔下，免费额度可支持约 300 个设备同时在线。**

### 10.4 心跳频率对比

| 心跳间隔 | 每日请求数/设备 | 支持设备数 |
|---------|----------------|-----------|
| 30 秒 | 28,800 | 3 个 |
| 1 分钟 | 14,400 | 6 个 |
| 5 分钟 | 2,880 | 34 个 |
| 10 分钟 | 1,440 | 69 个 |

### 10.5 优化策略

1. **5 分钟心跳**：平衡实时性与流量消耗
2. **30 分钟超时**：避免清理过于频繁
3. **批量清理**：每次请求只清理一次超时节点
