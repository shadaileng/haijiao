## 1. 需求概述

在设置页（SettingsView）添加以下功能：
- 显示用户金币和钻石余额
- 提供每日签到按钮

参考原始项目 `haijiao-wxt` 的实现方式。

---

## 2. API 端点

| 方法 | 端点 | 说明 | 参数 |
|------|------|------|------|
| POST | `/user/user_sign_in` | 每日签到 | 无 |
| GET | `/user/wealth` | 获取用户财富信息 | 无 |
| GET | `/task/getTaskStatus` | 获取任务状态（含签到状态） | 无 |

### 2.1 签到接口

**请求：**
```http
POST /user/user_sign_in
```

**响应：**
```json
{
  "success": true,
  "data": {
    "gold": 10,
    "连续天数": 5
  }
}
```

### 2.2 用户财富接口

**请求：**
```http
GET /user/wealth
```

**响应：**
```json
{
  "success": true,
  "data": {
    "gold": 1234,
    "diamond": 5678
  }
}
```

**注意：** 钻石值后端以分为单位存储，前端需除以 100 显示。

### 2.3 任务状态接口

**请求：**
```http
GET /task/getTaskStatus
```

**响应：**
```json
{
  "success": true,
  "data": {
    "goldSignIn": {
      "status": false
    },
    "vipChat": {
      "status": true
    }
  }
}
```

**状态语义（重要）：**
- `status: true` = **可以执行**（任务未完成，按钮可点击）
- `status: false` = **已完成**（任务已完成，按钮禁用）

**注意：** `goldSignIn.status` 字段语义与其他任务（如 `vipChat`）相反，是设计特性，不是 bug。

## 3. 类型定义

在 `src/types/index.ts` 中添加：

```typescript
// 签到结果
export interface SignInResult {
  gold: number        // 签到获得的金币
  consecutiveDays?: number  // 连续签到天数
}

// 用户财富
export interface UserWealth {
  gold: number         // 金币余额
  diamond: number      // 钻石余额（后端存储值，需除以100）
}

// 任务状态
export interface TaskStatus {
  goldSignIn: {
    status: boolean   // true=可执行(未签到), false=已完成(已签到)
  }
  vipChat: {
    status: boolean   // true=可执行(未领取), false=已完成(已领取)
  }
  // 其他任务状态...
  [key: string]: {
    status: boolean
  }
}
```

## 4. API 层修改

在 `src/api/request.ts` 的 `api` 对象中添加：

```typescript
// 签到
signIn: () => request<SignInResult>({ url: '/user/user_sign_in', method: 'post' }),

// 获取用户财富
wealth: () => request<UserWealth>({ url: '/user/wealth' }),

// 获取任务状态（含签到状态）
getTaskStatus: () => request<TaskStatus>({ url: '/task/getTaskStatus' }),
```

或使用独立函数形式：

```typescript
export const getTaskStatus = () => request<TaskStatus>({ url: '/task/getTaskStatus' })
```

```
┌─────────────────────────────────────┐

│  [立即签到]  已连续签到 5 天         │
├─────────────────────────────────────┤
│  登录状态        已登录             │
│  退出登录                         │
│  ...                               │
└─────────────────────────────────────┘
```

### 5.2 交互逻辑

1. **页面加载时**：
   - 调用 `/task/getTaskStatus` 获取签到状态
   - 调用 `/user/wealth` 获取余额并显示
2. **签到状态判断**：
   - 使用 `resp.data.goldSignIn.status` 字段
   - `status: true` → 显示"立即签到"（可点击）
   - `status: false` → 显示"已签到"（禁用）
3. **点击签到按钮**：
   - 调用 `/user/user_sign_in`
   - 设置 `signedIn = true`（不管 `resp.success`）
   - 刷新余额显示
   - 按钮变为"已签到"状态（禁用）

## 7. 注意事项

1. **钻石单位转换**：后端钻石以分为单位存储，前端显示需除以 100
2. **签到状态**：使用 `/task/getTaskStatus` 接口查询，`goldSignIn.status: false` 表示已签到
3. **状态语义**：`goldSignIn.status` 字段语义与其他任务相反（true=可执行，false=已完成），这是设计特性
4. **未登录处理**：未登录时不显示钱包和签到功能
5. **错误处理**：签到失败时显示 Toast 提示
