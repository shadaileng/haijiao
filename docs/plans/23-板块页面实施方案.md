## 1. 背景

当前 TabBar 仅包含「主页」「搜索」「配置」三个入口，缺少对社区「板块（Node）」的直接访问。用户浏览特定分类内容时需在搜索或首页间接查找，体验割裂。参照原版参考项目（`app.js` 中的 nodeTopics 调用），板块是核心导航维度之一，需独立建页并纳入底部导航。

## 3. 详细设计

### 3.1 TabBar 入口

在 `TabBar.vue` 的 `tabs` 数组中插入：

```ts
{ name: 'node', icon: 'category', to: '/node', label: '板块' }
```

Vant 的 `category` 图标表示分类/板块；若主题下无效果可使用 `list-o` 替代。

### 3.2 路由规划

| 路径 | 名称 | 组件 | TabBar 显示 |
|:----:|:-----|:------|:------------:|
| `/node` | `Node` | `NodeView.vue` | ✅ |
| `/node/:nodeId` | `NodeTopics` | `NodeTopicsView.vue` | ❌ |

`/node` 为板块列表页，TabBar 可见；`/node/:nodeId` 为板块帖子详情页，TabBar 隐藏（与其他子页面如 `/topic/:pid` 一致）。

### 3.3 API 层

#### 获取板块列表

后端接口 `/topic/nodes_by_ver/v2?ver=0` 返回所有板块信息（实际验证：`/topic/node` 返回 HTML 错误页，`/topic/nodes_by_ver/v2` 返回加密 JSON，解密后结构为 `{ list: [{ nodeId, parentId, name, icon, sortNo, description, display, vipLimit, external_url }] }`）。

> **注意**：`/tag/tags` 是标签列表 API，与板块（Node）是不同概念。板块是内容分类的主要维度（如"美女"、"热门"等），标签是内容的标记。

导出函数：

```ts
export async function getNodes(): Promise<any> {
  return request({ url: '/topic/nodes_by_ver/v2', params: { ver: 0 } })
}
```

扩展 `Api` 接口与 `api` 对象：

```ts
nodes(): Promise<ApiResult>
// ... 实现调用 getNodes() 并封装为 { success, data }
```

#### 获取指定板块下的帖子

接口 `/topic/node/topics` 传入 `nodeId` 和 `type=2`（节点主题）：

```ts
export async function getNodeTopics(
  nodeId: number,
  page: number,
  type = 2,
  limit = 20
): Promise<any> {
  return request({
    url: '/topic/node/topics',
    params: { nodeId, type, page, limit },
  })
}
```

扩展 `Api`：

```ts
nodeTopics(params: { nodeId: number; page: number; type?: number; limit?: number }): Promise<ApiResult>
```

### 3.4 NodeView — 板块列表页

**布局结构**（参考 HotTopicsView 风格）：

```
div.node-container
  div.node-header-sticky  ← position: sticky，标题固定顶部
    van-nav-bar            ← 标题"板块"
  van-skeleton             ← 加载中状态（骨架屏）
  van-empty                ← 无数据状态
  van-grid                 ← 3 列网格，每格显示 icon + 名称
```

**设计要点**：
- **sticky 标题**：`position: sticky; top: 0`，页面滚动时标题固定
- **窗口自然滚动**：不使用自定义滚动容器，与首页一致
- **van-grid 网格布局**：3 列网格，`van-grid-item` 显示图标 + 名称
- **keep-alive 缓存**：组件名 `NodeView` 加入 `App.vue` 的 keep-alive include 列表
- **滚动位置记忆**：scroll 事件监听 + sessionStorage 存储，onActivated 恢复

**滚动位置保存机制**：
1. `captureScroll` 在 scroll 事件中实时更新模块级变量 `savedScrollY`
2. 点击板块时 `goToNode` 将 `savedScrollY` 写入 `sessionStorage('scrollPos_Node')`
3. `onActivated` 读取 sessionStorage 并 `window.scrollTo` 恢复

**卡片交互**：点击 `van-grid-item` 跳转至 `/node/{nodeId}`。

**数据流**：
1. onMounted 调用 `api.nodes()` 获取板块列表
2. 结果映射为 Node 对象存入 reactive 数组 nodes
3. 渲染 van-grid 网格（128 个板块）

### 3.5 NodeTopicsView — 指定板块帖子页

**布局结构**：

```
van-nav-bar ← 标题显示板块名，左箭头返回
Topics      ← 复用现有 Topics 组件（mode="pagination"），加载该节点下的帖子
```

**数据流**：
1. 从 route.params.nodeId 读取节点ID（转为 Number）
2. onMounted 首次 loadPage(1)，watch 监听路由变化
3. api.nodeTopics({ nodeId, page, limit }) 请求数据
4. Topics 组件渲染 + 分页导航

**注意**：使用 `onMounted` 而非 `onActivated`，因为组件不在 keep-alive 缓存中。

### 3.6 滚动位置恢复

NodeView 使用窗口滚动（与 HotTopicsView 一致），通过 `captureScroll` 监听 scroll 事件实时记录 `savedScrollY`，点击板块时写入 `sessionStorage('scrollPos_Node')`，`onActivated` 恢复。

NodeTopicsView 不在 keep-alive 缓存中，每次进入重新加载。

## 5. 依赖假设与验证点

| 假设 | 验证方法 |
|------|---------|
| `/topic/nodes_by_ver/v2?ver=0` 返回板块列表 | 实际验证：`/topic/node` 返回 HTML 错误页；`/topic/nodes_by_ver/v2` 返回加密 JSON，解密后为 `{ list: [...] }` |
| 返回结构含 `nodeId`/`name`/`parentId`/`icon` 等字段 | 已通过 curl + Node.js 解密验证确认字段名 |
| `/topic/node/topics?nodeId=X&type=2` 可获取指定节点帖子 | 查阅 Haijiao 原始项目 `app.js` 中对应节点请求 |
| `LiteTopicPage` 响应结构兼容现有分页逻辑 | 对比 HotTopicsView 接收的响应格式 (`results` + `page`) |

如实际返回字段不同，需调整 `NodeView.vue` 中的数据映射逻辑。
