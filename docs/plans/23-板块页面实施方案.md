## 1. 背景

当前 TabBar 仅包含「主页」「搜索」「配置」三个入口，缺少对社区「板块（Node）」的直接访问。用户浏览特定分类内容时需在搜索或首页间接查找，体验割裂。参照原版参考项目（`app.js` 中的 nodeTopics 调用），板块是核心导航维度之一，需独立建页并纳入底部导航。

## 3. 详细设计

### 3.1 TabBar 入口

在 `TabBar.vue` 的 `tabs` 数组中插入：

```ts
{ name: 'node', icon: 'category', to: '/node', label: '板块' }
```

Vant 的 `category` 图标表示分类/板块；若主题下无效果可使用 `list-o` 替代。

### 3.2 路由规划

| 路径 | 名称 | 组件 | TabBar 显示 |
|:----:|:-----|:------|:------------:|
| `/node` | `Node` | `NodeView.vue` | ✅ |
| `/node/:nodeId` | `NodeTopics` | `NodeTopicsView.vue` | ✅ |

两个路由均开启 `showTabBar`，保证进入后 TabBar 可见。

### 3.3 API 层

#### 获取板块列表

后端接口 `/topic/node` 返回所有板块信息（参考 `03-Origin 代码剖析.md:287`：`1f24.e` → `/topic/node`）。

> **注意**：`/tag/tags` 是标签列表 API，与板块（Node）是不同概念。板块是内容分类的主要维度（如"美女"、"热门"等），标签是内容的标记。

导出函数：

```ts
export async function getNodes(): Promise<any> {
  return request({ url: '/topic/node' })
}
```

扩展 `Api` 接口与 `api` 对象：

```ts
nodes(): Promise<ApiResult>
// ... 实现调用 getNodes() 并封装为 { success, data }
```

#### 获取指定板块下的帖子

接口 `/topic/node/topics` 传入 `nodeId` 和 `type=2`（节点主题）：

```ts
export async function getNodeTopics(
  nodeId: number,
  page: number,
  type = 2,
  limit = 20
): Promise<any> {
  return request({
    url: '/topic/node/topics',
    params: { nodeId, type, page, limit },
  })
}
```

扩展 `Api`：

```ts
nodeTopics(params: { nodeId: number; page: number; type?: number; limit?: number }): Promise<ApiResult>
```

### 3.4 NodeView — 板块列表页

**布局结构**（与其他 Tab 页面风格统一）：

```
van-skeleton   ← 加载中状态（骨架屏）
van-empty      ← 无数据状态
van-grid       ← 网格展示每个板块卡片（3列，Vant 组件统一风格）
```

**设计要点**：
- **不使用 van-nav-bar**：TabBar 页面（Hot、Search、Settings）均无顶部导航栏，板块页保持一致
- **使用 van-grid + van-grid-item**：Vant 官方网格组件，样式统一
- **使用 van-skeleton**：加载态使用骨架屏，与其他页面一致

**卡片交互**：点击 `van-grid-item` 跳转至 `/node/{nodeId}`。

**数据流**：
1. onMounted 调用 `api.nodes()` 获取板块列表
2. 结果映射为 Node 对象存入 reactive 数组 nodes
3. 渲染 van-grid 网格

### 3.5 NodeTopicsView — 指定板块帖子页

**布局结构**：

```
van-nav-bar ← 标题显示板块名，左箭头返回
Topics      ← 复用现有 Topics 组件（mode="pagination"），加载该节点下的帖子
```

**数据流**：
1. 从 route.params.nodeId 读取节点ID（转为 Number）
2. onActivated 首次 loadPage(1)，复用分页逻辑
3. api.nodeTopics({ nodeId, page, limit }) 请求数据
4. Topics 组件渲染 + 分页导航

### 3.6 滚动位置恢复

同 HotTopicsView 模式：onDeactivated 保存滚动位置到 sessionStorage，路由 scrollBehavior 自动恢复。NodeView 和 NodeTopicsView 均在 keep-alive 缓存范围内（默认 App.vue 已 include）。

## 5. 依赖假设与验证点

| 假设 | 验证方法 |
|------|---------|
| `/topic/node` 返回板块列表（非标签） | 参考 `03-Origin 代码剖析.md:287`：`1f24.e` → `/topic/node` |
| `/topic/node` 返回结构含 `nodeId`/`nodeName` 等字段 | 运行后检查 API 响应，按实际字段调整映射 |
| `/topic/node/topics?nodeId=X&type=2` 可获取指定节点帖子 | 查阅 Haijiao 原始项目 `app.js` 中对应节点请求 |
| `LiteTopicPage` 响应结构兼容现有分页逻辑 | 对比 HotTopicsView 接收的响应格式 (`results` + `page`) |

如实际返回字段不同，需调整 `NodeView.vue` 中的数据映射逻辑。
