## 1. 问题概述

对 `src/` 目录下所有 API 调用的错误处理进行全面扫描，发现 **15 处**静默异常，分为以下几类：

| 类型 | 数量 | 严重程度 |
|:-----|:----:|:---------|
| 解密/解析失败仅 console.error | 2 | 高 |
| 完全空的 catch {} | 2 | 高 |
| catch 中仅降级返回原值 | 2 | 中 |
| 重试耗尽后返回 null（有兜底） | 1 | 低 |
| api 对象统一 try/catch 转返回值 | 11 | 低（设计模式） |
| await 无外层 try/catch | 5 | 中 |

---

## 2. 修复策略

### 2.1 错误分级处理原则

```
┌─────────────────────────────────────────────────────┐
│  错误等级  │  处理方式                 │  用户感知  │
├────────────┼───────────────────────────┼────────────┤
│ 严重       │ showToast + console.error │ 有提示     │
│ 一般       │ showToast                │ 有提示     │
│ 降级       │ console.warn + 空值兜底  │ 无提示     │
│ 合理静默   │ 空 catch（如对话框取消）  │ 无提示     │
└─────────────────────────────────────────────────────┘
```

### 2.2 关键原则

1. **全局入口必须有日志**：`request()` 函数的解密失败不能只 console.error，需要同时 `showToast`
2. **用户可见操作必须有反馈**：视频加载失败、图片解码失败等用户能感知的场景，必须提示
3. **降级场景保留空值兜底**：重试机制、无加密降级等场景，最终失败返回 null 是合理的
4. **对话框取消保持静默**：`showConfirmDialog` 的 `.catch(() => {})` 是 Vant 的标准用法，不修改

## 3. 详细修复方案

### 修复 1：全局请求解密失败 — 高优先级

**文件**：`src/api/request.ts:80-87`

**问题**：解密失败仅 `console.error`，`result` 保持原始加密数据（乱码），所有页面可能受影响。

**修复方案**：

```typescript
// 修复前
let result = data.data
if (data.isEncrypted) {
  try {
    result = JSON.parse(decodeEncrypted(String(data.data))) as T
  } catch (e) {
    console.error('decrypt error:', e)
  }
}

// 修复后
import { showToast } from 'vant'

let result = data.data
if (data.isEncrypted) {
  try {
    result = JSON.parse(decodeEncrypted(String(data.data))) as T
  } catch (e) {
    console.error('decrypt error:', e)
    showToast({ message: '数据解密失败，请检查镜像源配置', type: 'fail' })
  }
}
```

**影响范围**：所有 API 请求，仅在 `isEncrypted=true` 且解密失败时触发。

---

### 修复 2：视频加载全链路失败 — 高优先级

**文件**：`src/plugins/content.ts:394-396`

**问题**：视频加载 `.then` 链的顶层 catch 仅 `console.error`，视频区域永远停在加载图，用户无感知。

**修复方案**：

```typescript
// 修复前
.catch((err: any) => {
  console.error('load video error:', err)
})

// 修复后
.catch((err: any) => {
  console.error('load video error:', err)
  showToast({ message: '视频加载失败', type: 'fail' })
})
```

**影响范围**：所有视频播放场景。

---

### 修复 3：sell 视频解密失败 — 高优先级

**文件**：`src/plugins/content.ts:209-221`

**问题**：`catch {}` 完全空，sell 视频解密失败时 `videoAtta` 保持 undefined，用户看到空白区域。

**修复方案**：

```typescript
// 修复前
try {
  const vidId = Number(vidMatch[1])
  const data = await loadVideoSrc(vidId, topicId, '')
  videoAtta = { ... } as Attachment
} catch {}

// 修复后
try {
  const vidId = Number(vidMatch[1])
  const data = await loadVideoSrc(vidId, topicId, '')
  videoAtta = {
    id: vidId,
    coverUrl: data.coverUrl || '',
    keyPath: data.keyPath || '',
    video_time_length: data.video_time_length || 0,
    category: 'video',
    remoteUrl: data.remoteUrl || '',
    status: 1,
  } as Attachment
} catch (e) {
  console.warn('sell video load failed:', e)
}
```

**说明**：此处不需要 showToast，因为 sell 视频是预加载行为，失败后用户看到的是"此处为购买内容"的提示，属于可接受的降级。

---

### 修复 4：视频解析失败静默返回原对象 — 中优先级

**文件**：`src/api/request.ts:145-149`

**问题**：`getTopicWithVideo` 中视频解析失败返回原始附件对象，视频无法播放但无错误提示。

**修复方案**：

```typescript
// 修复前
if (item.category === 'video') {
  try {
    return await loadVideoSrc(item.id, topicId)
  } catch {
    return item
  }
}

// 修复后
if (item.category === 'video') {
  try {
    return await loadVideoSrc(item.id, topicId)
  } catch (e) {
    console.warn('video parse failed:', e)
    return item
  }
}
```

**说明**：保留返回原对象的降级行为（视频区域显示占位图），但增加 console.warn 便于调试。

---

### 修复 5：图片解码失败返回原始 URL — 中优先级

**文件**：`src/utils/image.ts:36`

**问题**：`.catch(() => item.remoteUrl)` 图片解码失败返回原始加密 URL，用户看到加密文本。

**修复方案**：

```typescript
// 修复前
.catch(() => item.remoteUrl)

// 修复后
.catch((e) => {
  console.warn('image decode failed:', e)
  return item.remoteUrl
})
```

**说明**：`loadImg` 已标记 `@deprecated`，保持降级行为但增加日志。

---

### 修复 6：异步 IIFE 无外层 catch — 中优先级

**文件**：`src/plugins/content.ts:201-403`

**问题**：`v-content` 指令中的 async IIFE 没有外层 `.catch()`，潜在 unhandled rejection。

**修复方案**：

```typescript
// 修复前
;(async () => {
  // ... 200+ 行异步逻辑 ...
  el.innerHTML = content
  // ... DOM 操作 ...
})()

// 修复后
;(async () => {
  // ... 200+ 行异步逻辑 ...
  el.innerHTML = content
  // ... DOM 操作 ...
})().catch((err) => {
  console.error('[v-content] render error:', err)
})
```

**说明**：保留 console.error，内部各子操作已有独立的 try/catch，外层仅兜底。

---

### 修复 7：onMounted / watch 中 await 无 try/catch — 中优先级

**文件**：`src/views/SettingsView.vue:21-26`、`src/views/UserHomeView.vue:29-48`

**问题**：`api.*` 方法内部已有 try/catch 返回 `{success:false}`，实际不会抛异常。但生命周期钩子中的 async 函数缺少保护。

**修复方案**：

```typescript
// SettingsView.vue 修复前
onMounted(async () => {
  if (settings.isLoggedIn) {
    await loadCurrentUser()
    loadingUser.value = false
  }
})

// SettingsView.vue 修复后
onMounted(async () => {
  if (settings.isLoggedIn) {
    try {
      await loadCurrentUser()
    } catch (e) {
      console.warn('load current user failed:', e)
    }
    loadingUser.value = false
  }
})
```

```typescript
// UserHomeView.vue 修复前
onMounted(async () => {
  if (userId.value) {
    await loadUserInfo(userId.value)
  }
  await loadPage(1)
})

// UserHomeView.vue 修复后
onMounted(async () => {
  try {
    if (userId.value) {
      await loadUserInfo(userId.value)
    }
    await loadPage(1)
  } catch (e) {
    console.warn('user home init failed:', e)
  }
})
```

**说明**：仅增加 console.warn，因为 `api.*` 方法不会抛异常，这里主要是防御性编程。

### 修复 8：获取解密密钥失败 — 低优先级（保持现状）

**结论**：重试机制 + 占位图兜底是合理的，保持现状，无需修改。

**文件**：`src/api/request.ts:248-335`

**结论**：这是**合理的设计模式**，将异常转化为结构化返回值。保持现状，无需修改。

## 6. 风险评估

| 修复项 | 风险 | 说明 |
|:-------|:-----|:-----|
| 1 - 解密 showToast | 低 | 仅在 `isEncrypted=true` 且解密失败时触发，正常情况不触发 |
| 2 - 视频加载 showToast | 低 | 视频加载失败本身就是异常场景，提示用户合理 |
| 3 - sell 视频日志 | 无 | 仅增加 console.warn，不影响逻辑 |
| 4 - 视频解析日志 | 无 | 仅增加 console.warn，保留降级返回 |
| 5 - 图片解码日志 | 无 | 仅增加 console.warn，保留降级返回 |
| 6 - IIFE catch | 低 | 仅兜底捕获未处理异常，内部已有独立 catch |
| 7 - 生命周期 catch | 低 | 防御性编程，api 方法本身不抛异常 |
